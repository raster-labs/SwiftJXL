# Grouped VarDCT decoder checkpoint

Pinned predecessor: `57e81cb9e2411d1efac435b429a306a031744c1e`; contract 0.10.0. The reader stitches DC samples, colour correlation, sharpness and transform coverage across DC groups. It reads deferred full-resolution alpha after AC tokens and supports an optional single simple global alpha palette (one channel, zero deltas, predictor zero, 1–65536 entries). Alpha inverse transforms use declared sample precision; DC/metadata retain their 16-bit transform domain.

Six independently encoded fixtures use pinned libjxl `a7a9c787341cf703dede03c2009fa460cae5e5df`, existing scalar build. The test-only `oracle.c` is the previous pixel wrapper with only the dimension ceiling raised from 1024 to 4096. No external library was rebuilt and no oracle enters runtime. `generate.py` records the synthetic formula and exact encode/decode commands; `cases.json` records geometry. Float32 explicit sRGB oracle output is rounded to meaningful integer precision. The existing peak ≤2 LSB/RMS ≤0.5 limits remain unchanged, and alpha is checked exactly against both source and oracle. These scalar numerical checks do not replace the previously retained ARM NEON integer differences.

Coverage: horizontal/vertical AC group boundaries, a two-dimensional AC grid, horizontal/vertical DC group boundaries, odd edges, RGB/grey, 8/16-bit samples and alpha, including a 16-bit grey-alpha palette stream. Destinations retain sentinel prefix/row padding and storage audit reports zero additional final-pixel allocations. New tests reject truncated grouped streams, insufficient operation memory and different DC extra precision. Existing frame and owning-storage regression suites are included in final runs.

All reads retain operation budget/deadline/cancellation checks and section-terminal checks. The existing envelope admits at most 16384 pixels per dimension and 64 million pixels, subject to the caller's tighter limits and workspace budget; the largest tested dimension here is 2057 and largest tested image is 257×259. Algorithm coefficient and alpha planes remain admitted workspace, not an extra final packed output. There is no measured peak-resident-memory or controlled performance claim.

Still unsupported: multiple passes; nonuniform per-DC extra precision (also rejected by pinned predecessor); global alpha Squeeze, multiple global alpha transforms and non-simple palettes; existing nondefault matrix/filter/profile limits. This is a qualified decoder checkpoint, not complete VarDCT interoperability, wider platform qualification or completed migration. Encoder grouping and public admission changes are separate work.

Source review by the coordinating agent found no blocking stitching, stream-ID or simple-palette issue; its alpha inverse precision concern was corrected before final validation. The initial plain SwiftPM invocation failed due to an inaccessible module cache, then the established in-workspace cache command was used. An initial test compilation mismatch and an initial insufficient-budget setup assertion were corrected before final runs. The initially rejected palette fixture was retained, implemented through the existing inverse transform, and passes the final six-case corpus.
