# Resource admission — public integer Modular profile

Contract 0.10.0 MEM-10–13 and TEST-06 control this implementation. These are conservative operation reservations, **not measured allocator/RSS peaks**. Unknown report measurements remain `nil`. The encoder supports unsigned greyscale/RGB with optional same-precision alpha through 16384 per axis at effort 3, subject to caller limits. The general decoder admits 1–16-bit grey/RGB with optional alpha, dimensions through 16384 per axis, caller-defined compressed/pixel/memory ceilings, entropy tables at most 32 MiB per reader and nesting at most 32.

## Admission model

`ScalarOperationBudget` uses checked arithmetic and an operation-local mutex. Workspace charges accumulate without release, so temporary table lifetimes cannot hide retained allocations. Independent workspace, decoded, compressed and aggregate ceilings apply. Aggregate admission includes retained source/input capacity (including padding and retained metadata), destination capacity, workspace and compressed output. A caller destination is charged before parsing; allocating decode reserves pixel capacity after supported headers and geometry are validated, before allocating. Inspection creates no pixel planes. An externally supplied destination's full capacity replaces the packed reservation before writing.

| Decode allocation group | Reservation before allocation |
| --- | --- |
| Extraction, reader and container inventory | `6*C + 256*min(4096,C/8) + 65536`, where C is retained compressed input size. Six input lengths cover extracted/concatenated Data, growth overlap, partial payload copies and the reader's byte copy. The per-box term covers box/partial/sorted inventory; parser count is capped at 4096. |
| Final samples | `2*N*channels` for allocating decode, or the actual entire caller-provided capacity (including UInt8 destinations), under both decoded and aggregate ceilings. |
| Pixel predictor and LZ77 history | `12*N + 192*(width+2) + 1024`: three history payload lengths cover append growth overlap; predictor rows require 48 bytes per extended column, with remaining allowance for row-array rounding/properties. Charged per decoded channel/section before writes. |
| Global/local trees | For each tree, `limit*(3*MemoryLayout<ModularTreeNode>.stride+72)+4096`, limit ≤4096. Includes node growth and at most six UInt32 history tokens per node with growth overlap. Both trees are charged when present. |
| Entropy headers | `(contexts+1)*64+32768` for each header, including nested maps: maps, MTF/seen state, configuration vectors and context-stream history. Contexts ≤4096; at most 256 histograms. |
| Prefix/ANS tables | Existing cumulative table admission now also debits the operation workspace/aggregate ledger. Prefix alphabet ≤65536: `40*alphabet + 8*32768 + 4096`; ANS: 65536 bytes per histogram; histogram inventory: 128 bytes each. These allowances cover construction temporaries, retained tables and stream alias state. |
| Modular geometry and planes | Geometry descriptors are admitted before transform planning (at most 4096 channels, 256 transforms). Each allocated Int32 algorithm plane reserves `4*sampleCount+64`. Inverse RCT reserves possible COW; Squeeze and palette reserve their restored planes before allocation. Group rectangles use separately admitted bounded planes only when transforms require them. |
| Sections and transforms | TOC entries reserve 128 bytes each; every reader is bounded to its exact section. Group descriptor/rectangle arrays are admitted before creation. ANS stream alias state reserves 64 KiB per histogram per stream. |
| ICC profile | Compressed ICC commands reserve `2*count+32768` before allocation; predictor output admission reserves `8*bytes+32768`. The decoded profile is limited to the minimum of the caller's ICC limit, aggregate metadata limit and 4 MiB. These charges use the same cumulative workspace ledger, including during inspection. A caller destination's retained ICC bytes are also charged to aggregate memory before parsing. |
| Unsupported payloads | Bounded extra-channel descriptors/names are admitted before parsing; unsupported semantics are rejected before pixel writes. Non-default tone mapping, unsupported colour interpretation, animation and unsupported extras are rejected. Without ICC, D65 and sRGB/BT.709 transfer are required; bounded required colour metadata counts against the metadata ceiling. Embedded grey/RGB ICC profiles are preserved without conversion; encoding ICC remains unsupported. |

The public decoder never calls the allocating `[Int32]` convenience decoder. Without global transforms it writes through `BorrowedModularChannel`, including independent group rectangles. Group-local transforms may require group Int32 workspace. Global transforms require signed Int32 algorithm planes (at least four bytes per transformed sample; inverse palette/Squeeze can overlap additional admitted planes); final reconstructed values are written from those planes into the caller's storage with no additional packed final-image allocation. Pointer lifetime stays inside the synchronous owner borrow. Reservations accumulate across groups and passes; they deliberately overestimate peak live workspace. Allocation-site audit counts controlled plane allocations, not allocator/RSS peaks. Operation report peak fields remain unknown (`nil`).

## General encoder envelope

The public encoder admits `N = width*height*channels` samples and `G = ceil(width/512)*ceil(height/512)` groups using checked arithmetic before allocating planes. Its compressed-output reservation is `B = min(6*N + 65536, maximumCompressedBytes)`. With `W = min(maximumWorkers, 8)`, workspace is conservatively `144*N + 192*(min(width,512)+2)*channels*W + 16384*G*channels + 6*B + 4194304*W`. This includes original Int32 planes, three RCT candidate planes, group rectangle scratch, both predictor/residual/symbol candidates, ANS pending/refill arrays, section/final buffers and capacity overlap. The per-sample term already sums the independent group and candidate arrays; the row and fixed-table terms now cover simultaneous workers. It is a cumulative admission bound, not measured peak RSS. The original narrow scalar internal entry remains available for baseline tests with its earlier envelope and one-worker default below.

Each parallel map additionally reserves `128 + 2*count*(stride(Result<T, Error>?) + stride(T))` bytes before creating its ordered result slots or dispatching work. This covers slot storage, the ordered output array and capacity/COW overlap; payloads referenced by those values are covered by the encoder envelope. The synchronous dispatch uses at most `min(W, count)` loop workers and joins them before extracting results in index order. Nested maps remain serial. Worker scopes explicitly inherit the operation budget and allocation audit. The public encoder's cancellation handler sets a shared monotonic flag, which worker checkpoints inspect together with deadlines and the output-overflow latch; checking task cancellation alone inside GCD work would be insufficient. No caller pixel pointer enters a worker closure. These changes are under validation and do not extend the supported effort/profile.

The public path preserves rendering intent for both colour interpretations and alpha association. Grouped rANS streams emit a 32-bit terminal state even when their global pixel stream is empty. Source ingestion, RCT/cost passes and grouped residual rows include cancellation/deadline checkpoints.

## Encoder envelope

For N samples and width W, output bound B is `min(maximumCompressedBytes, 6*N + 65536)`. The operation reserves B compressed bytes plus workspace:

```
88*N + 192*(W+2) + 6*B + 4194304
```

The 88*N term is twice the payload sum of the Int32 working plane (4*N), both gradient/weighted residual-and-symbol candidates (12*N), buffered ANS tuples (24*N) and refill words (4*N). It allows capacity/transient overlap without pretending these lifetimes are precisely measured. The row term covers both weighted predictor lifetimes. The 4 MiB fixed allowance covers the bounded raw4 alphabets (≤256), two retained gates, prefix LUTs, Huffman construction, ANS distributions/inversions and small headers. Six output lengths cover section/final writer backing buffers, Data conversion and growth overlap. The token bound is at most 15 prefix bits plus 28 extra bits, or 16 ANS refill bits plus 28 extra bits; six bytes per sample plus the fixed header allowance therefore bounds this profile.

`BitWriter` admits growth before appending and clamps speculative capacity requests. Its nonthrowing bit API latches overflow; bounded throwing checkpoints and final publication propagate `resourceLimitExceeded`. Frame and outer Data appends are checked separately before growth. Source copies, prediction rows, entropy costing/emission and ANS reverse/forward work have cancellation/deadline checks. Scratch candidate failures cannot swallow the operation's latched limit/deadline failure.

Entropy emission checks cancellation, deadline and the overflow latch before the first token and at intervals of at most 256 tokens, including zero-bit prefix symbols. Prefix counters belong to each bit writer; ANS uses its pending-token count. ANS finalisation also checks before allocating refill storage. Output-byte admission remains per write, and public publication performs its final operation check. This replaces expensive per-token clock/task-local/lock calls without allowing unchecked output growth. Regression tests cancel or latch a failure immediately after the first zero-bit token and require rejection within the next 256 tokens.

This envelope is intentionally conservative and may reject an image whose actual allocator peak would fit. It covers this exact effort/profile only; a broader codec path must receive a new audit and admission model. Heap overhead/runtime allocations are not an exact process RSS guarantee.

## Storage evidence and telemetry

`ScalarStorageAudit` instruments actual final-pixel and algorithm-working-plane allocation sites, scoped per task. `ScalarMemoryTests.publicSharedStorageUsesOnlyTheRequiredFinalAllocation` checks zero final allocations for source encode/caller decode, exactly one for allocating decode, one 4*N encoder plane, shared owner identity, and exact encoded bytes after padded-storage decode. The source audit above establishes that no uninstrumented final-image handoff path enters the public operations. Public oracle tests additionally compare full codestream bytes with direct scalar encoding and verify public results through libjxl in both directions at 9, 10, 12, 14 and 16 bits.

`Examples/MemoryProbe` uses the public API in an ordinary, unsanitized build. Its process heap snapshots complement allocation-site instrumentation; they are neither peak-workspace measurements nor exact per-operation deltas. Never run this allocator probe under a sanitizer. The captured run at 256 × 256 observed 262720 → 410416 bytes around allocating decode, and 558272 → 558320 around caller-storage decode; the final image payload is 131072 bytes. These values are observations from one warmed local run, not portable thresholds.

Broader profiles, release performance qualification, long-duration fuzzing, platform adapters and native JPEG reconstruction remain separate migration/release gates. No merge, stable release or production cutover follows automatically from this scalar integration.

## Broader ordinary-build ownership evidence — 12 October 2026

The unchanged `bfd12bc` runtime passed five [owning-memory probe cases](Evidence/ModularColour/Memory/README.md), from 512² greyscale through 2048² grey12 and 1024×1025 RGBA16. Allocation-site counters record exactly one final allocation for allocating decode, zero extra final allocations for caller decode/encode, exact samples, padding-independent encoded bytes and preserved caller allocation identity. Twelve shared-source concurrent operations passed across the smaller cases. Every profile passed preflight denial/reuse, cancellation invalidation and sealed-owner rejection. The probe uses explicit larger caller budgets for the large cases; production defaults are unchanged. Its cumulative plane payload counts, cumulative admission reservations and ordinary allocator snapshots are different measurements and are reported separately. They do not establish total peak workspace or controlled comparative performance.

Deliberate implementation mutants confirm the broader stride/byte-order checks are load-bearing: the same 68 parameter cases report 70 issues for packed-row addressing, 42 for forced big-endian handling, and zero after exact source restoration. These isolated diagnostic mutations are not committed runtime changes; patches, issue counts and restored hashes are retained with the memory evidence.

## Internal higher-effort candidate enforcement — 14 October 2026

Optional Modular candidates now propagate operation resource/cancellation failures; an exhausted worker-result reservation cannot silently return a lower-effort result. The shared single-section property pass also reserves its own incremental array/predictor workspace before allocation, using checked products and input-plane validation. See [the precise reservation, old/new reproduction and tests](MODULAR_EFFORT_LIMITS.md).

That initial shared-property reservation did not cover grouped buffers, routing/costing, sorting or learners. The [component-budget follow-up](MODULAR_EFFORT_BUDGET.md) now charges those components and selected emission cumulatively on top of the caller's effort-3 envelope, including all groups irrespective of the worker ceiling. It also bounds the changed learning/sorting loops. These conservative reservations do not establish allocator telemetry, a real-time cancellation guarantee or wider profile/platform qualification. Public effort stays at 3; its existing envelope is unchanged.


## VarDCT analysis workers and plan ownership — 15 October 2026

Hierarchical encoder search partitions only at aligned eight-cell (64-pixel) boundaries in both axes. At most `min(maximumWorkers, tileCount, 3)` workers read shared immutable owned working planes, quantisation fields and transform plans. No caller pixel pointer enters a worker. Each worker admits its small-transform scratch (4096 bytes plus 512-byte DCT scratch), large-transform scratch (64 DC Floats and 8192 DCT scratch Floats), and trial sample storage before allocating it, then reuses it across assigned tiles. A disjoint 192-Float prefix retains all three small-cell channels; one 4096-Float suffix serves the large transforms one channel at a time. The original three-large-channel admission is retained, although the payload is 32,000 bytes smaller per worker. Large-transform coefficients are a coordinate view into DCT output, eliminating a separate 4096-Float owner; the original conservative charge for that owner remains. Candidate trial charges remain cumulative even when a losing small-cell coefficient owner is reused. The existing image/cell envelope covers selection inventory and final coefficient packing, and the bounded map separately admits result slots before dispatch. Workers join on success, failure and cancellation before packing or publication.

Selected coefficient owners are retained for bounded batches of complete tile rows. Wide inputs use one row per batch; narrow inputs group enough complete rows to occupy the same worker ceiling. Each batch joins, sorts by global raster position and packs into the final coefficient arrays before the next batch begins. Persistent worker scratch resides in operation-local checked `Sendable` owners containing a `Mutex`; the exclusive synchronous borrow stores no raw pointer. Before any owner is allocated, admission reserves 64 bytes plus `workerCount * (referenceStride + 512)` for array, class and lock headroom. Scratch buffers retain their separate reservations. A failed later batch publishes no partial result, and its workers still join.

Plans are constructed only for reachable search-region sizes. Packed DCT matrices retain the per-plan reservation `32 * (ceil(rows/4)*rows + ceil(columns/4)*columns)`, storing Float-rounded coefficients in Double lanes. A construction-only axis bank shares immutable arrays within one operation and transform direction; cache hits retain admission and cancellation checks, and a different budget or direction rejects. The full hierarchy stores 43,648 matrix payload bytes instead of 213,504, excluding allocator overhead. Identical normalised transform shapes share immutable natural-order arrays, removing another 28,160 payload bytes while retaining each original per-strategy reservation. Large-transform DC factor caches reserve `8 * (2*cellsX*cellsY + cellsX*cellsX + cellsY*cellsY)` additional bytes. The one-worker path uses one search scratch and every path retains the same 4096 multiply-add checkpoint bound. Selected partitions and prepared pixel planes release before later coefficient/entropy construction where their lifetimes end. These admission bounds and payload counts are not process RSS measurements; controlled serial and public-default comparisons remain separate evidence.


Each selected hierarchical trial retains one contiguous Int32 owner, with each channel's DC rectangle followed by its AC plane. The admitted payload remains `3 * (coefficientCount + coveredCells) * 4` bytes per trial. A worker swaps its reusable losing candidate with the winner without sharing mutable storage with retained picks. Adaptive quantisation reuses one 192-Float patch while retaining its original per-cell charge and sample order. Final AC arrays reserve their exact `64 * cellCount` positions once within the existing image envelope. The operation-owned eight-bit preparation lookup separately admits 256 Doubles (2048 bytes), plus 256 Float triples (3072 bytes) for grayscale. Sample validation precedes indexing. Table construction checks cancellation at intervals of 64 entries; the scoped prefilter retains its existing 256-pixel checkpoint interval and Float arithmetic order. Executed validation and memory measurements are recorded in the [performance follow-up](MILESTONE4_PERFORMANCE_FOLLOWUP.md).


## Bounded Modular group decoding — 14 October 2026

Public decoding now propagates `ResourceLimits.maximumWorkers`, capped at eight. Independent AC groups within one pass may run in batches when the frame needs signed transform planes, or when an identity frame has at least 1,048,576 pixels. DC groups and pass boundaries stay ordered. Small identity frames and `maximumWorkers: 1` retain direct destination decoding. For direct-output frames, the batch limit is also capped at `groupCount - 1`, and parallel work requires at least two slots; no batch retains every tile of the image.

Each callback receives immutable compressed input and descriptor-only parent geometry, allocates only its group's admitted signed planes and entropy/predictor state, and returns owned samples. It never captures parent sample planes or the caller's raw destination pointer. `ModularChannel.allocatePixels` reserves `64 + 4*sampleCount` bytes before each group plane; existing group metadata, entropy, history and transform reservations remain cumulative across all batches. The batch helper reserves `128 + 2*count*(stride(Result<T, Error>?) + stride(T))` bytes before result-slot allocation and dispatch. Retained results are limited to one batch. No extra final image or full-frame handoff buffer is introduced; large identity decoding with multiple workers does use bounded group scratch instead of the zero-working-plane single-worker path.

Every callback joins before ordered results/errors leave the helper. The calling thread merges each completed batch serially, checking precision and preserving row gaps, endianness and caller allocation identity. Both public decode overloads install a cancellation handler that sets a shared monotonic flag; worker bit/token checkpoints consult that flag through the operation budget at the existing maximum interval of 256 operations. Reader-specific earlier deadlines remain enforced. All workers finish before failure/cancellation can invalidate the destination or release its borrow. The implementation and tests are prepared for the next coordinated validation run; these reservations are not measured process peaks or a latency claim.

## JPEG metadata parser admission — 15 October 2026

JPEG pixel inspection and decoding reserve the existing 64 KiB fixed parser/Huffman allowance before collecting frame components or ICC fragment records. ICC permits at most 255 fragments; their ranges borrow the retained compressed owner, and the assembled profile has its separate three-times-payload reservation before allocation. Exif copying and parsing retain their separate reservations. Moving the fixed allowance earlier preserves the total successful-operation charge for both DCT and SOF3. A regression supplies all 255 fragments and a late duplicate: insufficient workspace or aggregate memory must reject before the duplicate is parsed, while an admitted control still reports malformed input. The successful SOF3 control checks the exact total to prevent double-charging. This is admission-order evidence, not a measured allocator peak.
