# Embedded ICC pixel decoding

This stage extends the bounded integer Modular decoder to retain grey/RGB ICC profiles in `ImageDescriptor.iccProfile`. It performs no colour conversion, changes no pixel precision and keeps alpha association unchanged. Allocating decode and decode into caller storage preserve the same profile bytes. A caller destination with a different or missing profile rejects before pixel writes. Encoding with ICC remains explicitly unsupported, matching the pinned predecessor's encoder boundary.

The predecessor baseline is `57e81cb9e2411d1efac435b429a306a031744c1e`. Its best-effort inspection consumes ICC bytes, but that is not evidence of successful pixel decoding: its public decoder rejects all twelve independently encoded ICC fixtures with a frame-encoding error. [The probe and exact outputs](Evidence/ModularColour/ICC/preflight.json) preserve this distinction. SwiftJXL's pre-change tests rejected these inputs as unsupported; the new tests require exact profile and sample preservation.

The existing qualified `ICCStream` implementation is reused, retaining its Apache-2.0/BSD-3-Clause provenance. Inspection now decodes bounded colour metadata, never pixel planes. Both `maximumICCBytes` and aggregate `maximumMetadataBytes` apply before profile allocation, with an implementation ceiling of 4 MiB. Profile commands, prediction scratch and retained output are charged to the operation workspace; caller-owned profile bytes are additionally admitted with retained input. Profile size, `acsp` signature and RGB/GRAY component model must match. The profile is preserved as opaque colour interpretation; retaining it does not certify every ICC tag or implement a colour-management engine.

The twelve libjxl 0.12.0 fixtures cover one through four components and 8/12/16-bit precision at 513×3. Sample values are deterministic and compared in full, including caller allocation identity. Their profiles reuse the existing synthetic grey-gamma2.2 and sRGB fixtures with unchanged provenance. The [manifest](../../../../Tests/SwiftJXLCoreTests/Fixtures/Modular/ICC/manifest.json) records generator, commands and hashes. Additional checks cover profile-size limits, absent caller profiles, malformed ICC headers and truncated streams. A test helper initially misread a container as a raw codestream; it was corrected to extract the codestream before mutating the profile, and the affected tests were rerun.

CLI `inspect` and `validate` identify ICC interpretation and profile size. PNM/NRRD export refuses these inputs instead of dropping the profile or assigning sRGB. The existing independent CLI suite now includes these cases. Exact commands and configuration outcomes are in [validation evidence](Evidence/ModularColour/ICC/validation.json).

The earlier four one-hour campaigns passed 471158 mutations at the previous codec revision. They remain evidence for that scope, not qualification of this newly enabled ICC entry path. Extended ICC mutation testing, final-head hosted checks, controlled performance/memory and broader platform/codec/release gates remain separate work.
