## Implementation

- Constant images whose every channel has the same value use a zero-predictor tree leaf with that explicit offset and a single zero-bit prefix symbol. This eliminates pixel payload and empty ANS state overhead through a different conformant coding choice. Nonconstant ANS streams retain their required terminal states. The sample validation pass checks every input sample before this candidate is selected; a final sample/channel mismatch disables the path.
- Grouped residual trials borrow the validated original channel plane. Rectangle-local edge rules are retained; a temporary rectangle allocation and copy per predictor trial are removed. The same scoped neighbour access serves the single-section and RCT costing loops.
- Baseline ANS emission uses the compact single-cluster writer for both single and grouped sections. UInt16 symbol/refill storage plus one flag bit per token replaces the buffered token tuple and UInt32 refill arrays. Existing conservative admission is retained; this is not a claim of measured peak allocation or RSS savings.
- Inverse ANS alias maps use one contiguous slot array with per-symbol offsets. Single-cluster cost walks borrow the immutable tables across all tokens and traverse channel chunks in reverse without a full flattened symbol copy. Malformed cluster routing still rejects.
- Scaled DCT workspace calls borrow their two matrices and two uniquely owned scratch arrays synchronously. Four independent Double dot products share each input load without changing the sum order within any lane. The allocating scalar implementation remains the arithmetic reference. Plans store packed Double weights rounded through Float once; their larger storage is admitted before allocation. No pointer escapes. Workspace checks batch complete rows within the existing maximum of 4096 multiply-adds between cancellation/deadline checks, with start/end checks preserved.

- Small-transform scratch uses one admitted 276-Float allocation with ten disjoint synchronous slices, removing per-sample Array uniqueness checks. Large-transform DC extraction caches separate scale, normalisation and cosine factors without reassociating arithmetic.
- Hierarchical search reuses the last source patch across identical cell geometry, keeps every original strategy and quantisation trial, and compares partitions incrementally with the original tie priorities. Only reachable large-transform plans are constructed. Bounded workers search independent aligned 64×64-pixel tiles, sharing immutable planes/plans/QF and owning admitted scratch; global edge and quantisation coordinates remain unchanged. Only the current best and challenger remain live; final raster packing consumes selected coefficient owners incrementally instead of retaining a second complete representation. Prepared pixel planes release before entropy construction.
- Each worker reuses its transform scratch across all assigned tiles. Small-cell strategy trials reuse one losing coefficient owner per worker, swapping ownership with the selected candidate when its cost wins. Every DC and non-DC AC value is overwritten; the omitted AC DC positions remain zero. Selected coefficients have separate immutable owners when the cell returns. Adaptive quantisation reuses one 192-sample patch with the original channel and row-major summation order. Original per-trial and per-cell conservative admission charges, cancellation checks and tie rules remain in place.
- A construction-only axis bank shares identical immutable matrices across plans within one operation and direction. It removes 169,856 bytes of duplicate payload from the full hierarchy while preserving per-plan admission and cache-hit cancellation checks. Large-transform coefficient access maps directly into existing DCT output, removing a 16,384-byte owner and its copy per worker. Hierarchical VarDCT search uses at most three workers, with lower caller limits honoured; Modular worker policy is unchanged. Neither change alters transform candidates, coefficient arithmetic or output selection.
- Trial samples retain a disjoint 192-Float small-cell cache and one 4096-Float large-channel buffer. Large transforms consume channels sequentially with the original sample arithmetic; this removes 32,000 payload bytes per worker while retaining the original larger admission. Immutable natural scans share by normalised shape across strategies, removing 28,160 payload bytes without changing per-strategy charges. Decoder order-bucket tests cover all 21 strategies and eight distinct scan shapes.
- Search and packing advance through bounded batches of complete tile rows, reducing overlap between retained selected coefficients and the final AC arrays. Narrow images group enough rows to keep the bounded workers useful. All workers join before a batch is raster-sorted and packed; persistent scratch stays behind operation-local `Mutex` owners with admission before allocation. A later failure cannot publish earlier partial output. Tests compare every coefficient, transform and offset across square, narrow/tall and wide/partial shapes, caller ceilings two/three/eight, and a failure in a later batch.

## Prepared validation

`ModularConstantPerformanceTests` checks exact precision/samples across 512-pixel boundaries, 0/mid/max UInt16 constants, a 2048-square output ceiling of 363 bytes, multi-channel constants and final-sample disagreement. Independent oracle checks use the existing mandatory oracle environment. `CompactANSTests` compares chunked cost to emitted refill bits and covers invalid cluster routing. `VarDCTWorkspaceTests` compares each output bit pattern to the retained scalar implementation across both transform directions, 2–64 rows, three column sizes and repeated scratch reuse. Additional checks compare cached large-transform DC extraction bit-for-bit with its original uncached definition for all eleven shapes and verify cancellation before scratch writes at the smallest/largest axes. Exact plan-admission tests account for packed matrices. Existing group/effort, cancellation, malformed-input, storage, transform-oracle and sanitiser groups remain necessary.

After all implementation streams are complete, rebuild the final release candidate using `Scripts/TestSupport/pixel-family-benchmark.swift`. Reuse the prior pinned predecessor executable and oracle, then run:

```sh
python3 Scripts/TestSupport/milestone4-performance.py \
  --baseline-directory /path/to/prior/final/bench \
  --candidate /path/to/final/family-candidate \
  --output /path/to/new/results
```

The harness leaves the baseline directory untouched, performs new candidate independent/sample preflights, uses original shared decode inputs and eligibility, and executes ABBA then BAAB with five warm-ups and ten timed iterations per process (twenty per implementation per round). It records raw samples, binary/input hashes, process RSS, heap endpoints in raw process records, thermal state and size. Repeated >5% latency/RSS or >1% lossless size triggers produce a nonzero exit; no gate is silently waived. `--case` may narrow investigation, but a narrowed run does not qualify all retained cases. Native JPEG and JPEG pixel comparisons remain separate harnesses. Process-level RSS does not establish peak algorithm workspace, copy counts or leak freedom.

The retained one-worker pixel comparisons constrain the successor to one worker while the predecessor retains its native scheduling policy. They remain resource-constrained diagnostic evidence. A separate `--candidate-workers default` run compares actual public defaults using the same unchanged latency, RSS and lossless-size gates; it does not replace or rewrite the constrained rows. Modular predecessor group work uses `concurrentPerform` through its native `parallelMap`; successor bounded workers obey the explicit operation limit (public default eight). VarDCT predecessor search is serial but its transform kernels use Accelerate `vDSP_mmul`/`vDSP_mtrans` and cached Float matrices. The successor preserves its independent scalar arithmetic convention with operation-owned matrices and bounded tile workers. The one-worker comparison therefore does not hold the transform backend and scheduling policy constant. Successor tile parallelism is a measured optimisation; no observed difference is attributed solely to API overhead. Small/single-tile cases retain the same investigation thresholds.
