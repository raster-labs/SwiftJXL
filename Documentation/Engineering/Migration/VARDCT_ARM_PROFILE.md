# Explicit VarDCT integer-reference numerical profile

The historical ARM integer reference and the scalar Float32 reference use different numerical conventions. The default decoder retains exact scalar coefficient division and nearest-integer output. `DecoderConfiguration(varDCTNumericalProfile: .libjxl012ARMInteger)` explicitly selects the coefficient reciprocal estimate and integer-output quantisation conventions of libjxl 0.12.0 on ARM. This changes reconstructed lossy colour samples, preserves the declared sRGB interpretation and meaningful precision, and writes alpha exactly. Both allocating and caller-storage decoding use the selected profile; animation frame decoding inherits it. Modular decoding remains exact and unaffected.

```swift
let decoder = try Decoder(configuration: .init(
    varDCTNumericalProfile: .libjxl012ARMInteger))
let result = try await decoder.decode(compressed)
```

The selector is an opt-in compatibility convention, not a generally bit-exact libjxl implementation or a new fidelity guarantee. The original default-path ARM discrepancies are not reclassified as passes. Existing scalar tests and their maximum-two-level/RMS-0.5 thresholds remain unchanged. The new public-profile tests apply those same thresholds to the **unmodified original integer references**, with exact alpha. Qualification results must identify which profile was used.

## Arithmetic and source rationale

The pinned libjxl revision is `a7a9c787341cf703dede03c2009fa460cae5e5df`. Its [coefficient bias](https://github.com/libjxl/libjxl/blob/a7a9c787341cf703dede03c2009fa460cae5e5df/lib/jxl/quantizer-inl.h) uses an approximate reciprocal and fused negative multiply-add for coefficients with magnitude greater than one. Highway's ARM path uses the architectural reciprocal estimate. The explicit profile implements this mathematically in Swift: extract the normal Float32 exponent and the top eight fraction bits; round the reciprocal at the bin midpoint to eight fractional bits; reconstruct exponent and sign. This covers every Int32 coefficient, including `Int32.min`, without an absolute-value overflow or a fixture-derived coefficient table. The formula follows the reciprocal-estimate description in [Arm's architecture manual](https://documentation-service.arm.com/static/5f8dc043f86e16515cdbbc92). The default continues to use exact division.

The [pinned output writer](https://github.com/libjxl/libjxl/blob/a7a9c787341cf703dede03c2009fa460cae5e5df/lib/jxl/render_pipeline/stage_write.cc) adds its fixed blue-noise pattern for UINT8 output, with channel-dependent coordinate offsets, before clamping and nearest-even conversion. The explicit Swift profile uses that same 32-by-32 pattern, retaining its BSD attribution and [licence](../../ThirdParty/libjxl-LICENSE.txt). Its redundant SIMD wrap-padding columns are omitted. Dither follows eight meaningful bits regardless of whether the caller stores them in UInt8 or UInt16. Higher precision has no dither. Alpha bypasses this colour quantisation and remains exact. There is no host detection, reference-codec dependency, process invocation, image-specific lookup or file I/O in the codec.

The fixed pattern is 4 KiB of process-shared read-only data. Selection adds no image-sized allocation or frame copy. Existing operation budgets, cancellation checkpoints, borrowed destinations and ownership rules remain in effect. Latency and process-memory impact require measurement in the final validation phase.
